## 1. Project Overview & Objectives

This project demonstrates the end-to-end workflow of building, training, evaluating, and deploying a **Basic Feed-Forward Artificial Neural Network (ANN)** for a multiclass classification task.

Given two fundamental meteorological measurements:
1. **Temperature** in degrees Celsius (°C)
2. **Relative Humidity** as a percentage (%)

The neural network learns non-linear decision boundaries to classify the weather into three conditions:
- ☀️ **Sunny**
- ⛅ **Cloudy**
- 🌧️ **Rainy**

The application displays both the final predicted condition and the complete **Softmax probability distribution** (confidence scores across all three classes).

## 2. ⚠️ Important Educational Disclaimer & Limitations

> [!IMPORTANT]
> **This project is an educational demonstration designed for college coursework and viva examinations. It is NOT a real-world meteorological forecasting system.**

### Dataset & Physics Limitations:
1. **Synthetic Nature:** The dataset used here is synthetically generated for reproducible, transparent learning. It is not recorded from physical weather satellites or meteorological radar stations.
2. **Insufficient Features:** In the real world, temperature and relative humidity alone are mathematically insufficient to forecast the weather reliably. Professional meteorology requires barometric pressure gradients, wind velocity and direction, dew point, atmospheric lapse rates, cloud altitude, and historical pressure trends.
3. **Probability Meaning:** The probabilities generated by the model reflect its internal softmax activation based on training samples; they are **not** certified physical probabilities of tomorrow's actual weather.

## 3. Dataset Description & Generation Method

The dataset is located at `data/weather_data.csv` and contains **1,000 samples**.

### Generation Rules (`generate_data.py`):
The dataset was generated using fixed random seeds (`seed = 42`) following realistic meteorological distributions:
- **Sunny (~360 samples):** Mean Temperature = 30.0°C (warm/hot), Mean Humidity = 38.0% (dry to moderate).
- **Cloudy (~320 samples):** Mean Temperature = 22.5°C (mild), Mean Humidity = 68.0% (moderate to high).
- **Rainy (~320 samples):** Mean Temperature = 17.5°C (cool), Mean Humidity = 86.5% (high moisture/saturated).

To ensure realistic learning and avoid artificial 100% separability, ambient Gaussian noise was added to mimic real-world boundary overlap (e.g., humid sunny days or cool overcast afternoons).

### Features & Target:
| Column | Type | Range | Description |
| :--- | :--- | :--- | :--- |
| `temperature_c` | Float | 5.0°C to 45.0°C | Input feature 1: Ambient temperature |
| `humidity_pct` | Float | 15.0% to 99.0% | Input feature 2: Relative air humidity |
| `weather_condition` | String | Sunny, Cloudy, Rainy | Target class label |

## 4. Data Preprocessing Pipeline

Data preprocessing is strictly designed to avoid **data leakage**:

1. **Class Encoding:** Target categories are mapped to integer indices:
   - `Sunny -> 0`
   - `Cloudy -> 1`
   - `Rainy -> 2`
2. **Stratified Train-Test Split:**
   - 80% Training (800 samples)
   - 20% Held-Out Testing (200 samples)
   - `stratify=y` guarantees equal class balance across both splits.
   - Fixed `random_state=42` ensures exact reproducibility.
3. **Feature Standardization (`StandardScaler`):**
   - Formula: $z = \frac{x - \mu}{\sigma}$
   - Centers temperature and humidity to zero mean ($\mu = 0$) and unit variance ($\sigma = 1$).
   - **Crucial Best Practice:** The scaler is **fitted ONLY on the training set** (`scaler.fit(X_train)`) and then used to transform both train and test sets.
   - The fitted scaler is saved to `models/scaler.joblib` and re-used for real-time web inference.

## 5. Neural Network Architecture

The model is built using the **TensorFlow / Keras Sequential API**:

```
+-------------------------------------------------------+
|  Input Layer: 2 Features (Temperature, Humidity)      |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|  Hidden Layer: 8 Dense Neurons (Activation: ReLU)     |
+-------------------------------------------------------+
                           |
                           v
+-------------------------------------------------------+
|  Output Layer: 3 Dense Neurons (Activation: Softmax)  |
+-------------------------------------------------------+
```

### Why this architecture?
1. **Input (2 neurons):** Directly accepts the 2 normalized numerical features.
2. **Hidden Layer (8 neurons, ReLU):**
   - ReLU ($f(x) = \max(0, x)$) introduces non-linearity, enabling the network to learn non-linear decision boundaries between weather classes without the computational cost or vanishing gradient risk of sigmoid/tanh.
   - 8 neurons are sufficiently expressive for this 2D problem without causing overfitting.
3. **Output Layer (3 neurons, Softmax):**
   - Softmax transforms the 3 raw outputs (logits) into a normalized probability distribution where each value is in $[0, 1]$ and all three sum to exactly $1.0$.
4. **Loss Function (Sparse Categorical Cross-Entropy):**
   - Used for multiclass classification when true labels are integers ($0, 1, 2$) rather than one-hot vectors.
5. **Optimizer (Adam):**
   - Adaptive Moment Estimation adjusts learning rates per-weight, providing fast, smooth convergence.
